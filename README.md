# 動画制作エージェント Kairo

ローカル環境で完結する **動画制作エージェント** です。単なるAI動画編集ソフトではありません。素材と目的を渡すと、Kairo自身が

1. 継続的に収集・蓄積したトレンドを調べ、
2. ジャンルごとの作られ方（尺・Hook・カットテンポ・字幕量・BGM傾向）を参照し、
3. 手元の素材を解析し、
4. 企画・構成・Hookを立て、
5. ライセンスを確認したうえでフォント・BGM・効果音を選び、
6. 音楽のビートにカットを合わせ、
7. 字幕デザインを決め、
8. MP4を書き出し、
9. **書き出したMP4そのものを解析して採点し**、
10. 指摘を反映して作り直し、最もスコアの高い版を採用する

という一連の制作工程を自律的に実行します。制作中は「AIが今なにをしているのか」「なぜそれを選んだのか」が常に画面に表示され、チャットから「もっとテンポよくして」のように介入して実際のプロジェクトを変更できます。手動編集も従来どおり利用でき、AI生成と自由に組み合わせられます。

動画素材を1つも持っていなくても、最後まで再生できるMP4が完成します。外部クラウドサービスに動画や素材をアップロードすることはありません（外部に出るのは、任意機能のWebリサーチの検索クエリと、公開トレンドフィードへのGETリクエストだけです）。

バックエンドは Python (FastAPI)、フロントエンドは React (Vite)、動画処理は FFmpeg、文字起こしは faster-whisper、企画・脚本・分析・レビューはローカルで動く LM Studio（OpenAI互換API）を利用します。

> **正式名称について**: ユーザーに見える名称は「動画制作エージェント Kairo」です。既存環境を壊さないため、リポジトリ名・Pythonパッケージ名・データディレクトリ名・環境変数の接頭辞 (`KAIRO_`) などの内部識別子は `kairo` のまま変更していません。

## 🚀 最短起動 (Windows / PowerShell)

すでに Node.js と Python がインストールされていれば、以下だけで開発サーバーが立ち上がります。

```powershell
# 1. リポジトリを取得
git clone <このリポジトリのURL>
cd Kairo

# 2. 依存関係のインストール + 初回セットアップ (venv作成・pip install・npm install・.env作成)
npm run setup

# 3. 開発サーバーを起動 (バックエンド + フロントエンド)
npm run dev
```

起動したら、ブラウザで **http://localhost:5173** を開いてください。

> AI編集・AI自動制作機能を使う場合は、事前に [LM Studio](https://lmstudio.ai/) を起動し、Local Server を有効にしておく必要があります（詳細は [LM Studioのセットアップ](#lm-studio-のセットアップ) を参照）。動画の読み込み・書き出し・無音カット・字幕生成には [FFmpeg](https://www.gyan.dev/ffmpeg/builds/) が必須です（`npm run setup` が未検出時に警告します）。

## プロジェクト概要

動画制作エージェント Kairo は、素材の取り込み → トレンド調査 → 企画・構成 → 素材/フォント/BGM/効果音の選定 → 編集 → 字幕 → 書き出し → 完成動画の採点 → 自動改善、という一連の制作フローをブラウザUIから実行できるローカル動作のエージェントです。手動でのタイムライン編集・無音カット・字幕生成も従来どおり使えます。

クラウドAPIキーは不要です。LLMは LM Studio 等のローカルサーバー、動画処理は FFmpeg、文字起こしは faster-whisper、音声合成は Windows 標準の SAPI5 と、主要機能はすべてローカルで完結します。トレンド収集だけが外部の公開フィードを読みますが、これが使えなくても動画制作機能は停止しません。

## 3つの制作モード

Kairoを開くと、まず作り方を選びます。どのモードで作ったプロジェクトも、後からモードを行き来できます。

| モード | 概要 | 向いている場面 |
|---|---|---|
| **⚡ Full Auto** | 一言入力して放置するだけ。企画から書き出しまでAIが最後まで進めます | とにかく1本作りたい |
| **💬 AI Co-Creation** | AIが制作を進めつつ、チャットの指示で実際のプロジェクトを変更します | 方向性を調整しながら作りたい |
| **✂ Manual** | 素材読み込み・タイムライン編集・字幕・書き出しを自分で行います | 自分の素材で細かく作りたい |

### Full Auto の流れ

```
一言の指示（＋あれば自分の写真・動画）
  ↓ 制作環境確認 → AIモデル確認 → 素材解析 → Webリサーチ → トレンド分析 → 制作戦略
  ↓ 企画 → 脚本 → Scene設計 → 素材マッチング → 素材生成 → 音声
  ↓ BGM/SFX（ライブラリから選定 + ビート同期）→ 字幕（フォント選定）→ 編集
  ↓ 品質チェック → 自動改善 → 再チェック → プレビュー → 書き出し
  ↓ 完成動画レビュー（実測採点）→ 自動改善ループ（再書き出し・最良版採用）
MP4完成 + 制作レポート + assets-used.json
```

23の工程それぞれについて、**現在のフェーズ / 現在の作業 / 対象 / 目的 / 使用モデル / 次の処理** が画面に表示されます。制作中はいつでも一時停止・停止でき、再開すると完了済みの工程はやり直さず途中から続きます。

最後の2工程が「動画制作エージェント」としての中核です。**完成動画レビュー**は計画ではなく書き出されたMP4そのものを開き、尺・解像度・ラウドネス（EBU R128）・フレーム輝度を実測して7軸で採点します。**自動改善ループ**はその指摘を反映して作り直し、スコアが最も高かった版を最終版として採用します。

素材を渡した場合は、**素材解析**（何が写っているかを把握）が脚本より先に走り、脚本はその素材で撮れている画を前提に書かれます。**素材マッチング**でどのシーンにどの素材を使うかが決まり、足りないカットだけが補完されます。素材を渡さない場合、この2工程は「素材なし」としてスキップされ、これまでどおり最後まで自動で完成します。

### AI Co-Creation の流れ

チャットの指示は返答で終わりません。AIが現在のScene・尺・字幕・タイムラインを読んだうえで**変更案**を提示し、「適用」を押すと実際のプロジェクトが書き換わります（尺が変わったシーンは映像も再生成され、字幕とBGMも同期し直されます）。気に入らなければ「元に戻す」で戻せます。

```
「もっとテンポよくして」
  → AIが現在の構成を分析
  → 変更案: 全体の尺 69秒 → 59秒（理由付き）
  → [適用] → 全シーン再生成 + 字幕再同期 + タイムライン更新
  → [元に戻す] でいつでも復元
```

## 主な機能

- **AI制作スタジオ (Full Auto / AI Co-Creation)**: 一言の指示からMP4完成まで。23工程の進捗・AI作業状況・使用モデルをリアルタイム表示
- **Trend Intelligence**: バックグラウンドWorkerがGoogle Trends / Wikimedia Pageviews（任意でYouTube Data API）から継続的にトレンドを収集してDBに蓄積。ジャンル別に分類し、時間経過でスコアを減衰させます。詳細は[Trend Intelligence](#trend-intelligenceトレンド収集分析)
- **Creative Asset Library + License Manager**: フォント・BGM・効果音をライセンス情報つきで管理。**ライセンスが確認できない素材は自動制作で使用しません**。詳細は[ライセンス管理](#asset-license-managerライセンス管理)
- **Font Intelligence**: フォントファイルのcmap/PANOSE/OS-2テーブルを実際に読み、日本語対応・字形・太さ・可読性・ジャンル適性を判定して字幕書体を選定します
- **Audio Intelligence / Beat Sync**: BGMのBPM・拍位置・ラウドネスを実測し、カット位置を拍に合わせます
- **AI Video Reviewer**: 書き出したMP4を実測して7軸（Hook/テンポ/映像/字幕/音/構成/トレンド適合）で採点し、「問題 → 原因 → 改善案」を提示します
- **Auto Refinement**: レビュー結果を制作エンジンに戻して再制作。反復回数の上限があり、最もスコアの高い版を採用します
- **A/B/Cバリエーション**: 同じ企画を情感重視/テンポ重視/トレンド寄せの3通りで作り直し、レビュー点で比較して最良版を選びます（明示実行）
- **Webリサーチ → 制作戦略**: 同じテーマの動画がどう作られているかを調べ、「共通トレンド」と「差別化機会」に分けて抽出し、Hook・テンポ・字幕方針・音・終わり方を決めた制作戦略に落とし込みます（模倣ではなく傾向の参考として利用）
- **ショート動画向けScene設計**: シーンごとに尺・目的・感情・カメラ・映像内容・字幕・効果音・トランジションを設計。ナレーションと画面上の字幕は別物として扱います
- **ユーザー素材からの自動編集**: オートモードの開始画面で写真・動画をドラッグ＆ドロップすると、AIが内容を解析し、台本・ナレーション・構成に合わせて並び順・使用時間・カット位置を決めて編集します。詳細は[ユーザー素材について](#ユーザー素材写真動画について)
- **素材ゼロでの制作**: 手持ち素材がなくても、シーンの感情と内容から配色・光・粒子・構図を組み立てて映像素材を生成します（ダウンロード不要・CPUのみ）。ユーザー素材がある場合は必ずそちらが優先されます
- **ナレーション・BGM・効果音**: Windows標準の音声合成でナレーションを生成し、実測の長さに合わせてシーン尺を自動調整。BGMは雰囲気に合わせて生成し、ナレーション中は自動的に音量が下がります（サイドチェイン・ダッキング）
- **品質チェックと自動改善**: 書き出し前に構成・テンポ・Hook・つながり・字幕・音・終わり方などを点検し、直せる問題は自動修正して理由とともに提示。直せない指摘は「自動修正不可」と明示します（書き出し**後**の実測レビューは別工程です）
- **接続サービスの可視化**: LLM・FFmpeg・faster-whisper・TTS・トレンド取得元・素材取得元の接続状態を、表示のたびに実際に確認して一覧表示します
- **AIモデル管理**: 今回どのAIを何に使うのかを動的に表示。LM Studioのモデルは「ダウンロード済み」と「メモリに読み込み済み」を区別し、未準備の場合は具体的な対処手順を案内します
- **一時停止 / 停止 / 再開**: 制作中に中断でき、再開時は完了済み工程をスキップして途中から続行します
- **ユーザー向けログと技術ログの分離**: 通常は日本語の作業ログ、必要なときだけリクエストやFFmpegの詳細を展開
- **プロジェクト管理**: 複数の動画プロジェクトを作成・切り替え
- **メディア読み込み**: 動画/音声ファイルをドラッグ&ドロップで取り込み
- **タイムライン編集**: クリップの追加・削除・分割・トリム・音量調整、ドラッグ&ドロップでの並び替え
- **プレビュー再生**: タイムラインの内容をブラウザ上でそのまま再生確認
- **無音自動カット**: 無音区間を検出し、まとめてカットするプランを適用（`AI編集`パネルの元になっている機能）
- **字幕自動生成**: faster-whisper によるローカル文字起こしから字幕(SRT)を生成・編集
- **AI編集 (自然言語)**: 「無音部分を削除して、字幕をつけてください」のような指示をLLMに渡し、タイムライン操作を自動実行
- **AI自動制作**: テーマを指示するだけで、LLMが企画・章立て・シーン単位の台本とビジュアル指示を自動生成
- **画像→動画生成 (実験的)**: 写真をアップロードし、ローカルのStable Video Diffusionモデルで短い動画を生成(`生成`タブ)。完全ローカル・CPU実行、生成結果はMedia Binに自動追加されます。詳細は[動画生成機能](#動画生成機能-実験的)を参照
- **PC / AI環境診断**: CPU・RAM・GPU・ストレージ・FFmpeg・PyTorch等を自動検出し、このPCで何が実行可能かを表示(`PC診断`タブ)
- **レンダリング (書き出し)**: FFmpegでタイムラインを1本の動画に書き出し。字幕の焼き込みにも対応
- **ジョブ進捗表示**: 字幕生成・AI編集・レンダリング・動画生成などの非同期処理をバックグラウンドで実行し、進捗をポーリング表示

## Trend Intelligence（トレンド収集・分析）

Kairoは動画を作る直前にだけ検索するのではなく、**バックグラウンドWorkerが継続的にトレンドを収集してDBに蓄積**します。制作時はその蓄積を参照するため、ネットワークが落ちていても制作が止まりません。

```
Trend Worker (起動時に開始, 既定3時間ごと)
    ↓ 定期取得
    ↓ 正規化 (NFKC + 大文字小文字 + 空白)
    ↓ 重複排除 ((platform, keyword, region) で一意)
    ↓ ジャンル分類
    ↓ Trend Score（時間経過で半減期30時間の減衰）
    ↓ DB保存 (trend_signals テーブル)
```

### 取得元

| 取得元 | 種別 | APIキー | 内容 |
|---|---|---|---|
| Google Trends | 公開RSS | 不要 | `https://trends.google.co.jp/trending/rss?geo=JP` の急上昇ワードと推定検索数 |
| Wikimedia Pageviews API | 公式API | 不要（User-Agent必須） | 前日の最多閲覧記事（一般的な関心の指標） |
| YouTube Data API v3 | 公式API | **必要** (`KAIRO_YOUTUBE_API_KEY`) | `chart=mostPopular` の人気動画・カテゴリ・再生数。キー未設定時は自動的に無効 |

TikTok と Instagram Reels は **接続していません**。一般公開のトレンドAPIが提供されておらず、規約上スクレイピングもできないためです。この事実は設定画面の「トレンド」タブに理由つきで表示されます（表から消すのではなく、未接続であることを明示します）。

### ジャンル別の分析

収集したキーワードは旅行・動物/ペット・料理・ゲーム・Vlog・美容・教育・エンタメ・スポーツ・テクノロジー・ニュース・ビジネスの12ジャンルに分類されます。どのジャンルの語彙にも一致しないものは **「分類なし」のまま**にします（近いジャンルに押し込むと、間違ったジャンルの動画が組み立てられるため）。

ジャンルごとに次の傾向を保持します。

- 想定尺 / 1カットの長さ / Hook秒数
- Hookの型・冒頭構成
- カットテンポ・字幕量・字幕位置・字幕スタイル
- フォントの方向性・BGMの雰囲気・BPM帯
- 効果音の使い方・トランジション・タイトル/CTAの型

この傾向には2つの根拠レベルがあり、UIには**必ずどちらかが表示されます**。

- **「Kairo組み込みの定石」** — ショート動画のフォーマット知識です。トレンドの実測値ではありません
- **「トレンドN件から分析」** — そのジャンルのトレンドが5件以上溜まったときに、ローカルLLMが実際に分析した結果です

### 設定

設定画面の「トレンド」タブから、収集のON/OFF・対象地域・更新頻度（30分未満は設定できません。他社のサーバーへの負荷を避けるためです）・制作時に使うかどうかを変更できます。「今すぐ更新」で手動収集も可能です。

## Creative Asset Library（素材ライブラリ）

`data/library/` 配下に、Kairoが自動制作で使える素材を集約します。

```
data/library/
├── fonts/
│   ├── jp/      # 日本語のみ
│   ├── en/      # 欧文のみ
│   └── multi/   # 日本語+欧文
├── music/
│   ├── cinematic/  travel/  vlog/  emotional/  energetic/
│   └── comedy/  ambient/  warm/  modern/  neutral/  tense/
└── sfx/
    ├── whoosh/  hit/  pop/  click/  transition/  cinematic/
    ├── sparkle/  surprise/
    └── nature/  water/  ambient/   # 取り込み専用（合成音源はありません）
```

素材は2系統から集まります。

1. **Kairoが生成したもの** — FFmpegで合成したBGM（11カテゴリ × 2テンポ = 21曲）と効果音（8種類）。第三者の権利が含まれないため無条件で使用でき、**生成時にテンポを指定しているのでビート位置が正確に分かります**。オフライン環境でもライブラリが空になりません
2. **ユーザーが取り込んだファイル** — 上記フォルダに置いて「再スキャン」すると取り込まれます。取り込み直後のライセンスは「不明」で、**自動制作には使われません**

`nature` / `water` / `ambient` に合成音源を用意していないのは意図的です。サイン波を「波の音」と称して並べるより、取り込み専用フォルダとして空にしておく方が正直だからです。

すべての音源は取り込み時に実測されます（長さ・BPM・拍位置・ラウドネス LUFS）。

## Asset License Manager（ライセンス管理）

すべての外部素材は次の6状態のいずれかに分類されます。

| 状態 | 意味 | 自動制作での扱い |
|---|---|---|
| 使用可能 | 条件なしで利用可（OFL-1.1 / Apache-2.0 / CC0 / Kairo生成 など） | 使用する |
| 帰属表示必要 | 利用可、クレジット必須（CC-BY など） | 使用し、クレジットを `assets-used.json` に自動記録 |
| 条件付き | 特定条件下でのみ利用可（OS同梱フォント＝この端末での描画のみ、再配布不可） | 使用する（条件を満たすため） |
| 商用利用不可 | CC-BY-NC など | **使用しない** |
| 利用不可 | 個別許諾が必要 | **使用しない** |
| ライセンス不明 | 権利が確認できていない | **使用しない** |

**「無料っぽいから使う」という判断がコード上できない構造**になっています。素材の選定は `services/library/selector.py` を通り、スコアリングの**前に**ライセンス状態でフィルタされるため、どんな重み付けでもライセンス不明の素材が選ばれることはありません。使える素材が1つも無ければ「無い」と報告し、条件を満たさない素材の中から最良のものを返すことはしません。

取り込んだファイルのライセンスは、設定 > 素材ライブラリ から選択して設定できます。設定内容はDBと同時にファイル横の `<ファイル名>.kairo.json` にも書き込まれるため、DBを作り直しても失われません。

## AI編集ディレクター（今回のKairo編集方針）

編集を始める前に、**どういう動画を作るか**を決める工程です。Full Auto の
`編集方針決定` フェーズで一度だけ実行され、以降の全ステージ（脚本・フォント選定・
カット編集・画面切り替え・字幕・色・音）は、この1つの決定を読んで動きます。

決めるもの:

| 項目 | 内容 |
|---|---|
| ジャンル / 編集スタイル | Trend Intelligence のジャンル判定 + 依頼文のキーワード |
| 配信先 | YouTube Shorts / TikTok / Instagram Reels / YouTube 16:9 |
| 動画尺・画面サイズ | 配信先の上限で丸めます |
| テンポ / 1カットの長さ | スタイルの既定値をジャンル傾向と素材数で調整 |
| ストーリー構成 | Hook→Introduction→…、Arrival→Location→… など |
| 字幕方針 | 量・位置・縁取り・サイズ倍率・アニメーション・強調の有無 |
| フォント方針 | 求める印象（高級感/カジュアル/シネマティック/インパクト）とウェイト帯・可読性の下限 |
| 画面切り替え方針 | 使ってよい種類と、**全カット中の上限割合** |
| BGM方針 | 雰囲気・BPM帯・音量・ダッキング・環境音の残し方・効果音の密度 |
| 色味 | Clean / Warm / Cinematic / Bright / Moody / Retro / Travel |
| 写真の動き | Ken Burns の強さと、優先する動き |

決定は4層で、後の層が前の層を**調整**します。UIには「どこまでの根拠で決まったか」が
`defaults` / `defaults+profile` / `defaults+profile+ai` として表示されます。

```
① 編集スタイル（10種の定石）      … 必ず存在する。モデルもトレンドも無くても方針は出ます
② ジャンル傾向（Trend Intelligence）… 実測値がある項目だけ上書き
③ 素材の実態                      … 素材が11カット分しかなければ1カットを伸ばす、
                                     写真中心なら動きを強める、暗い素材を更に暗くしない
④ ローカルLLM                     … 雰囲気・テンポ・色・字幕量・切り替え量・フォントの印象を調整。
                                     許可された語彙の外の値は破棄されます
```

### ジャンル別編集スタイル（10種）

Vlog / Travel / Cinematic / Food / Tutorial・解説 / Entertainment / SNS Shorts /
Documentary / Luxury / Casual。それぞれカットテンポ・字幕・フォント方針・
画面切り替え・BGM・色味・写真の動き・テロップ量・効果音量を持ちます。
固定テンプレートではなく、上の③④で素材とAIが調整します。

制作画面の **編集方針** タブに、決定内容と理由がすべて表示されます。

## 画面切り替え（Transition）の決め方

**カットが既定です。** 切り替えは「意味のある箇所」にだけ入れます。

境界ごとに、次の順で理由を探します。

1. シーン設計で明示的に指定された切り替え
2. 意味のある変化 — 幕の変わり目 / 時間の経過 / 場所の移動 / 感情の切り替わり / 被写体の連続
3. 音楽の区切り（Beat Sync が成立している場合のフレーズ境界）
4. 上のどれでもなければ **カット**

そのうえで、編集スタイルが決めた**上限割合**を適用します。理由の弱い候補から落とすので、
幕の変わり目は残り、ついでの場所移動が落ちます。

実測例（Vlog / 24カット・23境界）: 切り替え候補20箇所 → **実際に使ったのは3箇所**
（すべて幕の変わり目）。ログには落とした理由も残ります。

FFmpeg の `xfade` で描画できるものだけを語彙にしています:
カット / フェード / クロスディゾルブ / ディップ・トゥ・ブラック / スライド(左右上) /
プッシュ / ズーム / マッチカット。

切り替えは尺を消費します（D秒の切り替えは前後から合計D秒を取る）。前後のカットが
0.4秒未満になる場合や、どちらかの40%を超える場合は、その境界はカットのままにします。

## 色味（カラーグレーディング）

動画全体で1つの色味に統一します。`eq` と `colorbalance` を使った控えめな補正で、
彩度は最大±35%、コントラストは±25%、明るさは±10%に制限しています。LUTのような
置き換えは行いません（素材本来の色を壊さないため）。

素材が暗い場合は暗くする方向の補正を弱め、明るくする方向に切り替えます。
素材が既に明るい場合はこれ以上明るくしません。

適用はレンダリング時（`normalize_segment`）に1回だけです。セグメントキャッシュの
キーに色味が含まれるので、色を変えて再レンダリングすると確実に再エンコードされます。

---

## 字幕を「デザイン」として扱う

字幕は文章ではなく、1つ1つがデザインです。キューごとに次を決めます。

- サイズ倍率 / 太さ / 位置 / 字間 / 行間
- 表示アニメーション（なし / フェード / ポップ / 下から）
- **強調語** — 数字・最上級・英単語を1行に最大2語まで拾い、その語だけ大きく太くします
  （ASS のインライン `\fscx` `\b1`）。行全体を大きくするのは強調ではないためです。
- 冒頭の字幕は、インパクトを求めるスタイルでのみ大きく強く出します

字幕量もスタイルが決めます。Vlog は全カットには付けず、内容の薄いキューから落とします
（実測: 24件 → 17件）。落とした件数と理由はログとUIに出ます。

---

## 写真の動き（被写体を外さない Ken Burns）

写真には Pillow で**細部の重心**を求め、それを被写体位置として扱います
（顔認識ではありません。UIにもそう表示されます）。

- 縦型に切り出したあとの被写体位置を計算してから動きを決めます
- 移動中ずっと被写体が画面内（安全域の内側）に残るよう、始点と終点を制限します
- クロップで被写体が画面外に出る場合は「画面外になるため中央基準」と明示します
- 写真が連続するときは動きの種類を順に変えます（ずっと寄り続けるのを避けるため）

## 素材の品質評価

アップロードされた素材について、明るさ・色・動きに加えて次を測ります。

| 指標 | 方法 | 用途 |
|---|---|---|
| シャープネス | ラプラシアン分散をコントラストで正規化 | ピンボケの検出 |
| 手ブレ | フレーム間ズレの**ばらつき**（大きさではなく） | パンと手ブレの区別 |
| 被写体位置 | 細部の重心 | Ken Burns の基準点 |
| 重複 | 16x16 平均ハッシュのハミング距離 | 同じ画の連続を防ぐ |
| 品質スコア | 上記と明るさから0-100 | 選別とランキング |

**被写体が一致していれば、多少眠い素材でも使います**（内容が合っている方が重要なため）。
一方、内容が一致しない素材を「余った素材」として画面を埋めるためだけに使う場合は、
ピンボケ・低品質のものは使いません。使わなかった素材と理由はUIに表示されます。

## Kairo Style Memory（好みの記録）

`data/style_memory.json` にローカル保存されます。2種類を**明確に分けて**扱います。

- **あなたが変更した設定** → 次回の制作の出発点になります（明示的な変更が常に優先）
- **Kairoが選んだもの** → 好みとしては扱いません。毎回同じフォントにならないよう、
  直近で使った書体の優先度を下げるためだけに使います

設定 > 好みの記録 で内容の確認と削除ができます。傾向は「3件」のように件数で表示し、
「あなたの好み」とは書きません（3件は好みではないため）。

## Font Intelligence（フォント選定）

フォントを「PCにインストールされている名前の一覧」としては扱いません。フォントファイルのバイナリを実際に読み、次を判定します。

| 項目 | 判定方法 |
|---|---|
| 日本語対応 | `cmap` テーブルで「あ」「ア」「日」「本」の実在を確認（ファイル名からの推測ではありません） |
| 欧文対応 | 同上（A / a / 0） |
| 字形（セリフ/サンセリフ/丸ゴシック/装飾/手書き） | `OS/2` の PANOSE 分類。日本語特有の命名（明朝・ゴシック・丸ゴ・UD）は**追加**のみに使い、ファイルの申告を上書きしません |
| 太さ | `OS/2` の usWeightClass |
| 可読性 | x-height比・ウェイト・字幅・装飾性から算出する**Kairoの推定値**（実測の可読性テスト結果ではありません。UIにもそう表示されます） |
| ジャンル適性 | 上記タグからの決定的なマッピング |

この端末では446件のシステムフォントを約1.3秒でスキャンできます。追加依存関係（fontTools など）は使わず、必要な4テーブルだけを読む実装です。

### フォントの自動取得

設定 > 素材ライブラリ から、Google Fonts公式リポジトリ（`google/fonts`）経由で追加できます。

```
カタログ表示
 ↓ ライセンスファイル(OFL.txt)を先に取得   ← 取得できなければダウンロード中止
 ↓ フォント本体をダウンロード
 ↓ <ファイル名>.kairo.json に出典・ライセンス・ライセンスファイルの位置を記録
 ↓ Kairo Font Libraryへ保存 → メタデータ登録 → 利用可能化
```

**ライセンスファイルが取得できない場合はフォントをダウンロードしません。**「たぶん大丈夫」という経路は用意していません（実際、M PLUS Rounded 1c は配布ディレクトリに OFL.txt が無いため、カタログから除外されています）。

日本語フォントを重点的に収録しています（Noto Sans JP / Zen Maru Gothic / Zen Kaku Gothic New / BIZ UDPGothic / Shippori Mincho / Dela Gothic One / Kiwi Maru / Mochiy Pop One ほか、全25ファミリー）。

## Audio Intelligence と Beat Sync

BGMは「雰囲気」だけで選ぶのではなく、**実測値**で選びます。

- **BPM**: FFmpegでデコード → スペクトルフラックスのオンセット包絡 → 自己相関でテンポ推定。既知テンポのクリック音源で検証済み（128BPM → 127.6、90BPM → 90.7）
- **拍位置**: 推定テンポの周期にオンセットのエネルギーが最も乗る位相を探索
- **ラウドネス**: FFmpeg の EBU R128（`ebur128`）で統合ラウドネス（LUFS）とピーク（dBFS）
- **長さ**: デコード実長

拍が明確に検出できない音源（環境音・パッドなど）では **BPMを `null` として返します**。ここで適当な120を返さないことが重要で、Beat Syncは「テンポ不明」を受け取ると拍合わせをやめてシーン境界でカットします。

### Beat Sync

```
BGM beat（実測 or 生成時に指定した値）
  ↓ beat timestamps
  ↓ 1カットに何拍を割り当てるか決定（戦略上のカット長に最も近い倍数）
  ↓ 各シーンの尺をグリッドにスナップ
  ↓ cut points → transition → SFX
```

ナレーションの実測長に合わせて決まったシーン尺を大きく引き伸ばすと音声がカットをはみ出すため、**1シーンあたりの移動量は35%までに制限**しています。それを超える場合はそのシーンだけ拍合わせを見送ります。

### 効果音の自動配置

冒頭（Hook）、場面転換、締めに絞って配置します。字幕やシーン設計が明示的に効果音を指定している場合はそちらを優先します。**1分あたり最大12個**の上限があり、上限に達したときは場面転換の分から間引きます（Hookと締めは残ります）。過剰使用は「効果音を入れた」ではなく「うるさい」になるためです。

## AI Video Reviewer（完成動画レビュー）

書き出したMP4を**実際に開いて**採点します。制作前の「品質チェック」（構成の点検）とは別工程で、UIのタブも分かれています。同じ動画で両者の評価が食い違うことがあり、その食い違いこそ見る価値があるためです。

| 軸 | 何を見るか |
|---|---|
| Hook | 冒頭シーンの長さ、冒頭字幕の有無、暗いフレームの有無 |
| テンポ | 平均カット長とジャンル傾向の差、突出して長いカット、計画尺と実測尺のズレ |
| 映像 | 抽出した8フレームの平均輝度・コントラスト・フレーム間変化（暗すぎ/白飛び/変化なし） |
| 字幕 | 字幕の表示時間比率、字幕なしシーン、長すぎる字幕 |
| 音 | EBU R128 統合ラウドネス（目安 -14 LUFS）、ピーク、音声トラックの有無 |
| 構成 | シーン数、オチ/余韻の有無、同内容カットの重複 |
| トレンド適合 | 尺・カット長がそのジャンルの傾向とどれだけ合っているか |

各軸には**根拠の種別**が併記されます。

- **実測** — MP4から読み取った値
- **構成から** — ファイルからは分からないためシーン設計から判断した値
- **AI判断** — ローカルLLMの所見

この区別を表示するのは、根拠のたどれない数値は数値が無いより悪いためです。トレンドデータを使っていない制作では、トレンド適合軸は0点ではなく**総合点の計算から除外**されます（評価できない軸で減点するのは不当なため）。

指摘は「**問題 → 原因 → 改善案**」の3点セットで提示され、自動修正できるものには「自動修正可」、できないものには「自動修正不可」が明示されます。

## Auto Refinement（自動改善ループ）

```
Generate → Render → Review → Improve → Render → Review → Best Version
```

**無限ループは構造的に発生しません。** 次のいずれかで必ず停止します。

1. 設定の最大反復回数に到達（既定2回、上限5回）
2. 目標スコアに到達（既定85点）
3. 前回からの改善幅が小さい（既定2点未満）
4. 自動修正できる指摘が残っていない
5. 修正を適用しても実際の変更が生じなかった

最後の版ではなく、**最もスコアの高い版を採用**します。改善が裏目に出ることは実際にあるためです（例: 尺をジャンル傾向に合わせて伸ばした結果、テンポと構成の点が下がって総合点が落ちる）。採用しなかった版のMP4もジョブIDごとにディスクに残ります。

自動修正できる指摘の種類:

| 修正 | 内容 |
|---|---|
| `set_duration` | 特定シーンの尺を変更（該当シーンを再エンコード） |
| `fill_subtitle` | 字幕のないシーンにナレーションから字幕を生成 |
| `shorten_subtitle` | 長すぎる字幕を句読点位置で短縮 |
| `rescale_total` | 全体の尺を目標に合わせて比例調整 |
| `raise_bgm` / `lower_bgm` | BGM音量を調整（測定したLUFS差をリニアゲイン比に換算） |

### A/B/C バリエーション

同じ企画を「情感重視 / テンポ重視 / トレンド寄せ」の3通りで作り直し、レビュー点で比較できます。Studio画面の「完成動画レビュー」タブから実行します。

| ID | 名前 | 何を変えるか |
|---|---|---|
| A | Emotional | カットを約1.2倍に伸ばし、落ち着いたBGM（低テンポ帯）を選ぶ |
| B | Fast Pace | カットを約0.8倍に詰め、速いBGMを選び、字幕の文字数上限も25%短くする |
| C | Trend-oriented | そのジャンルのトレンド傾向が示すカット長・尺・BGMに寄せる |

**変えるのは「同じ企画の見せ方」だけ**です。シーン・台本・字幕の文言は企画段階で決まったものをそのまま使います。3本が別々のアイデアになってしまうと比較する意味が無くなるためです。各バリエーションは3つとも変更前の尺を基準に作られ（Bが「Aの結果をさらに詰めたもの」にならないように）、実行後はシーンの尺が元の企画値に戻されます。

3本ぶんの書き出しとレビューが走るため、Full Autoの標準フローには含めていません（明示的に実行したときだけ動きます）。書き出したMP4は3本ともディスクに残るので、「Bが最良」という判定はAとCを実際に見て確認できます。

| その他必須ソフト | [FFmpeg](https://www.gyan.dev/ffmpeg/builds/)（動画処理全般に必須）、[LM Studio](https://lmstudio.ai/)（AI編集/自動制作機能を使う場合のみ必須） |

## 起動方法

### 開発モードの起動方法

バックエンド (uvicorn --reload) とフロントエンド (Vite dev server) を同時に起動します。ファイルを保存すると自動で再読み込みされます。

```powershell
npm run dev
```

- バックエンド: http://127.0.0.1:8756 （Swagger UIは http://127.0.0.1:8756/docs ）
- フロントエンド: http://localhost:5173

バックエンドとフロントエンドを別々のターミナルで個別に起動したい場合:

```powershell
# ターミナル1: バックエンドのみ
backend\.venv\Scripts\python -m uvicorn app.main:app --reload --port 8756 --app-dir backend

# ターミナル2: フロントエンドのみ
npm --prefix frontend run dev
```

### 本番モードの起動方法

フロントエンドをビルドし（`dist/`が無ければ自動でビルドしてから）、ホットリロード無しでバックエンドとフロントエンドのプレビューサーバーを起動します。

```powershell
npm run start
```

- バックエンド: http://127.0.0.1:8756 (`--reload`なし)
- フロントエンド (ビルド済みファイルの配信): http://localhost:4173

フロントエンドだけを先にビルドしたい場合は `npm run build` を単体で実行できます（`frontend/dist/` に出力）。

## 停止方法

`npm run dev` / `npm run start` を実行しているターミナルで **Ctrl+C** を押してください。バックエンド・フロントエンドの両方のプロセスがまとめて停止します（片方が異常終了した場合も、もう片方を自動的に停止します）。

個別に `uvicorn` や `vite` を起動していた場合は、それぞれのターミナルで Ctrl+C を押してください。

## LAN内の別端末からアクセスする方法

デフォルトでは `127.0.0.1` / `localhost` からのアクセスのみを許可しており、LAN内の他の端末（スマホ・タブレット・別PCなど）からは開けません。対応させるには以下の手順を行ってください。

1. **このPCのLAN IPアドレスを確認する**

   ```powershell
   ipconfig
   ```

   `IPv4 アドレス` の値（例: `192.168.1.20`）を使います。

2. **バックエンドをLAN公開用に起動する** (`KAIRO_HOST` を `0.0.0.0` に設定)

   `backend/.env` に以下を追加する（`npm run dev` / `npm run start` の両方が読み込みます）:

   ```
   KAIRO_HOST=0.0.0.0
   ```

   一時的にこの回だけ変更したい場合は、`.env` を編集する代わりに実行前にPowerShellの環境変数として設定しても構いません:

   ```powershell
   $env:KAIRO_HOST = "0.0.0.0"
   npm run dev
   ```

3. **バックエンドのCORS許可オリジンにLAN側フロントエンドのURLを追加する**

   `backend/.env` を編集し、以下の行を追加（`192.168.1.20` は手順1で確認した自分のIPに置き換え）:

   ```
   KAIRO_CORS_ORIGINS=http://192.168.1.20:5173
   ```

4. **フロントエンドのAPI接続先をこのPCのIPに向ける**

   `frontend/.env` を編集し、以下のように設定:

   ```
   VITE_API_BASE=http://192.168.1.20:8756
   ```

5. **フロントエンドもLAN待受で起動する**

   ```powershell
   npm --prefix frontend run dev -- --host 0.0.0.0
   ```

6. 別の端末のブラウザで `http://192.168.1.20:5173` を開く

Windows Defender ファイアウォールの確認ダイアログが出た場合は、プライベートネットワークでのアクセスを許可してください。設定を元に戻す場合は、`backend/.env` の `KAIRO_HOST` / `KAIRO_CORS_ORIGINS` と `frontend/.env` の `VITE_API_BASE` の変更行を削除またはコメントアウトしてください（PowerShellの `$env:KAIRO_HOST` で一時設定した場合は、新しいターミナルを開けば解除されます）。

## 環境変数の設定方法

環境変数は `backend/.env` と `frontend/.env` の2つのファイルで管理します（どちらも `.gitignore` 対象で、Gitにはコミットされません）。`npm run setup` を実行すると、それぞれのサンプルファイルから自動生成されます。手動で作る場合は次の通りです。

```powershell
Copy-Item backend/.env.example backend/.env
Copy-Item frontend/.env.example frontend/.env
```

### `.env.example` の説明

- **`backend/.env.example`**: バックエンド (FastAPI) が読む環境変数のサンプルです。データ保存先、素材ライブラリの保存先、LM StudioのURL/モデル名/タイムアウト、faster-whisperのモデルサイズ/実行デバイス/演算精度、LAN公開時の追加CORSオリジン、任意の外部APIキーをコメント付きで記載しています。値を省略した項目は、コード側 (`backend/app/core/config.py`) のデフォルト値が使われます。

> **APIキーについて**: KairoはAPIキーをソースコードに書き込みません。すべて `.env`（Git管理外）から読み込み、未設定の場合はその機能だけを無効にして他は通常どおり動作します。有料APIを既定で有効にすることもありません。
- **`frontend/.env.example`**: フロントエンド (Vite) が読む環境変数のサンプルです。バックエンドAPIのベースURL (`VITE_API_BASE`) のみを定義しています。Viteの仕様上、`VITE_` で始まる変数だけがブラウザ側コードから参照可能です。

主な設定項目 (`backend/.env`):

| 変数名 | デフォルト値 | 説明 |
|---|---|---|
| `KAIRO_DATA_ROOT` | `<リポジトリルート>/data` | 動画・DB・ログの保存先ディレクトリ |
| `KAIRO_LLM_BASE_URL` | `http://localhost:1234/v1` | LM Studio (OpenAI互換API) のベースURL |
| `KAIRO_LLM_MODEL` | (未設定=自動検出) | LM Studioに渡すモデル名。未設定の場合、Kairoが起動時にLM Studioの`/v1/models`から利用可能なモデルを自動検出し、PC性能に応じて推奨されるモデルを自動選択します（Kairo UIの「設定 > AI」からAuto/Manualの切り替え・モデル変更も可能）。 |
| `KAIRO_LLM_TIMEOUT` | `120` | LLMリクエストのタイムアウト秒数 |
| `KAIRO_WHISPER_MODEL` | `small` | faster-whisperのモデルサイズ (`tiny`/`base`/`small`/`medium`/`large-v3`) |
| `KAIRO_WHISPER_DEVICE` | `cpu` | 文字起こしの実行デバイス (`cpu` / `cuda`) |
| `KAIRO_WHISPER_COMPUTE` | `int8` | 演算精度 |
| `KAIRO_CORS_ORIGINS` | (空、未設定) | LAN公開時などに追加で許可するオリジン（カンマ区切り） |
| `KAIRO_LIBRARY_ROOT` | `<KAIRO_DATA_ROOT>/library` | 素材ライブラリ（フォント・BGM・効果音）の保存先 |
| `KAIRO_YOUTUBE_API_KEY` | (空、未設定) | **任意**。YouTube Data API v3 のキー。設定するとトレンド取得元としてYouTubeの人気動画が有効になります。未設定なら該当取得元は「未設定」と表示され、他の取得元だけで動作します |
| `KAIRO_MAX_UPLOAD_BYTES` | `2147483648` (2GB) | 1ファイルあたりの取り込み上限 |
| `KAIRO_HOST` | `127.0.0.1` | (npm scriptsが参照) バックエンドの待受アドレス |
| `KAIRO_PORT` | `8756` | (npm scriptsが参照) バックエンドの待受ポート |

主な設定項目 (`frontend/.env`):

| 変数名 | デフォルト値 | 説明 |
|---|---|---|
| `VITE_API_BASE` | `http://127.0.0.1:8756` | フロントエンドが呼び出すバックエンドAPIのURL |

## データベースの初期化

Kairo は SQLite (`data/kairo.db`) を使用しています。テーブルはバックエンド起動時 (`backend/app/main.py` の `on_startup`) に `SQLAlchemy` の `create_all` で **自動作成**されるため、通常は追加の初期化コマンドは不要です。

明示的にDBだけを初期化したい場合（初回セットアップの動作確認や、DBファイルを作り直した直後の確認など）は以下を実行してください。

```powershell
npm run db:init
```

> このプロジェクトには現時点でマイグレーションツール（Alembic等）は導入されていません。テーブル定義 (`backend/app/models/`) を変更した場合は、開発中であれば `data/kairo.db` を削除して `npm run db:init` するか、次回起動時の自動作成に任せてください（既存データが必要な場合は事前にバックアップしてください）。

## LM Studio のセットアップ

AI編集（自然言語での編集指示）とAI自動制作（企画・台本の自動生成）機能は、ローカルで動くLLMサーバーを利用します。このプロジェクトは [LM Studio](https://lmstudio.ai/) を前提にしていますが、OpenAI互換の `/v1/chat/completions` APIを持つ他のローカルサーバーでも動作します。**クラウドAPIへのフォールバックは一切行われません**（LM Studioに接続できない場合は、AI機能がはっきりしたエラーメッセージで失敗します）。

1. **LM Studioをインストール**: https://lmstudio.ai/ からダウンロードし、インストーラーを実行
2. **モデルを用意**: LM Studioのホーム画面の検索から、日本語に対応したチャット/instructモデル（例: `google/gemma-3-...`, `Qwen2.5-...-Instruct` など、お使いのPCのメモリに合ったサイズのもの）をダウンロード
3. **LM Studioを起動**: アプリを開き、ダウンロードしたモデルを画面上部からロード
4. **Local Serverを起動**: 左側のサイドバーから `Developer` (`</>` アイコン) タブを開き、`Start Server` をクリック（デフォルトポートは `1234`）
5. **必要なAPI URLを設定**: デフォルトでは `backend/.env` の `KAIRO_LLM_BASE_URL=http://localhost:1234/v1` のままで動作します。LM Studioのポートを変更した場合のみ、この値をLM Studio側の表示に合わせて変更してください
6. **アプリを起動**: `npm run dev` でKairoを起動し、エディタ画面上部（編集タブ）またはAI制作タブに表示される **「LM Studio: 接続済み」** の表示を確認

接続状況は `GET /api/llm/status` でも確認できます。

```powershell
curl http://127.0.0.1:8756/api/llm/status
```

LM Studioが起動していない・Local Serverが無効な場合は、UI上に **「LM Studio: 未接続」** と表示され、AI編集/AI自動制作を実行するとジョブが失敗し、「LM Studioに接続できません」という具体的な日本語エラーメッセージがジョブのステータス欄に表示されます（`backend/app/services/llm_client.py`）。動画の読み込み・タイムライン編集・字幕生成・レンダリングなど、LM Studioを使わない機能は影響を受けず通常通り利用できます。

## AIモデルの準備

Kairoは制作を始める前に、**今回どのAIを何に使うのか**を一覧で表示します（Full Auto / AI Co-Creationの開始画面右側、および制作中の左サイドバー）。モデル名はすべてLM Studioとこのマシンの実際の状態から解決され、ハードコードされたモデル名は一つもありません。

| 役割 | 使用するもの |
|---|---|
| 企画・構成 / 脚本・Scene生成 / リサーチ分析 / 品質チェック / AI Co-Creation | LM Studio のチャットモデル |
| 映像素材生成 | Kairo Composer（ローカル合成・ダウンロード不要） |
| 音声合成 | Windows SAPI（インストール済みの音声） |
| 動画編集・書き出し | FFmpeg |

### ダウンロード済みとロード済みの違い

LM Studioの `/v1/models` は「ダウンロード済み」のモデルをすべて返すため、メモリに読み込まれていないモデルも一覧に出ます。Kairoは LM Studio の `/api/v0/models` から実際の状態を取得し、以下を区別して表示します。

- **● メモリに読み込み済み** — すぐに応答が返ります
- **○ ダウンロード済み** — 最初のリクエスト時にLM Studioが自動で読み込むため、**初回だけ数十秒〜数分かかります**（この旨は開始画面に警告として表示されます）

「今すぐ読み込む」ボタンから事前に読み込んでおくこともできます。

### 必要なモデルが無い場合

Kairoが**勝手に大容量モデルをダウンロードすることはありません**。未準備のときは、開始画面に何が足りないかと具体的な手順が表示され、制作開始ボタンは無効になります。

```
⚠ このままでは制作を開始できません
LM Studio(http://localhost:1234/v1)に接続できません。

・LM Studioを起動する
・LM StudioのDeveloper(Server)タブでLocal Serverを起動する
・エンドポイントが合っているか確認する
```

### モデルの選び方

「モデルを選ぶ」から、用途・量子化・サイズ・コンテキスト長・読み込み状態つきの一覧を見て選べます。「自動選択に戻す」を押すと、KairoがPCのメモリとGPUに合わせて選び直します。

**モデルサイズと速度**: 7B前後のモデルをCPU/内蔵GPUで動かす場合、脚本生成の1リクエストに数分かかることがあります。制作が遅いと感じたら、より小さいモデル（2B〜4B級）に切り替えると大幅に速くなります。応答が制限時間内に返らない場合は「AIモデルの応答が時間内に返りませんでした」という専用のエラーが表示され、小さいモデルへの切り替えが提案されます（待ち時間の上限は `KAIRO_LLM_TIMEOUT`、既定600秒）。

## ユーザー素材（写真・動画）について

オートモード（Full Auto / AI Co-Creation）の開始画面は、次の順番になっています。

```
① 作りたい動画   「この写真と動画を使って沖縄旅行の30秒Shortsを作って」
② 素材           写真・動画をドラッグ＆ドロップ（任意）
③ 動画設定       縦型 9:16 / 30秒
④ 制作開始       素材プランを確認して開始
```

**素材は必須ではありません。** 何も渡さなければ、必要な素材はKairoが用意します。

### 対応形式

| 種類 | 拡張子 |
|---|---|
| 写真 | `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.gif` `.tif` `.tiff` |
| 動画 | `.mp4` `.mov` `.mkv` `.webm` `.avi` `.m4v` |
| 音声 | `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg` |

複数ファイルを一度に投入できます。読み込めなかったファイルがあっても、他のファイルの取り込みは続行され、**そのファイルだけ**「何が原因か」と「どうすればよいか」が表示されます（例:「動画コーデックが対応していません」「ファイルサイズが大きすぎます」）。

### 素材解析

アップロードされた素材は次のように解析され、タグが付きます。

- **Vision対応モデルがLM Studioにロードされている場合**: 画像/動画のフレームをそのモデルに見せ、写っているもの（海・飛行機・夕日・人物・食事など）を認識します。素材カードには「AI画像解析」と表示されます
- **ロードされていない場合**: 画像認識は行いません。解像度・向き・明るさ・動きの量・ファイル名から推定し、「ファイル名・画像情報から推定」と明示します（AIが見たかのように見せることはしません）

動画については、長さ・縦横・明るさ・動きの量に加えて、**使用可能な区間**（先頭や末尾の真っ暗な部分を除いた範囲）を判定し、カットはその区間から取られます。

### 素材の使い方

| モード | 動作 |
|---|---|
| **AIにおまかせ**（既定） | 内容が合う素材をAIが選び、順番・使用時間・カット位置を決めます |
| **できるだけ全部使う** | アップロードした素材をできる限りすべて登場させます |
| **選択した素材だけ使う** | チェックを入れた素材だけを使います |

### 素材の優先順位

映像に使う素材は、必ずこの順で選ばれます。

1. ユーザーがアップロードした**動画**
2. ユーザーがアップロードした**写真**
3. ローカル素材（※Kairoにはまだ共通のローカル素材ライブラリがないため、現状この段は常に空です）
4. ライセンスを確認できるWeb素材（Openverse / Wikimedia Commons。CC・パブリックドメインのみ）
5. AI生成素材（Stable Diffusionを導入している場合のみ）
6. 抽象背景（Kairoが構成する映像）

**ユーザー素材が残っているのに抽象背景が使われることはありません。** 内容が一致する素材がない場合でも、余っているユーザー素材が先に配置されます（その場合は「内容の一致は確認できていません」と理由に表示されます）。

補完に使えるソースは環境によって変わるため、**実際に使えるものだけ**が素材プランに表示されます。ネットワークが使えない場合は「Web素材は利用できません」、Stable Diffusion未導入なら「AI画像生成モデルは未導入です」と明示され、抽象背景で補完されます。

### 素材プラン

制作開始前に、素材の状況が表示されます。

```
素材プラン
  ユーザー素材   写真：8枚 / 動画：3本
  不足素材       沖縄のブランコ：1 / 海岸の動画：1
  補完方法       Web素材：1 / AI生成：1
```

開始前は**見込み**（シーン数がまだ決まっていないため）、素材マッチング工程の完了後はシーンごとの実際の割り当てが表示されます。

### 完成後の確認

完成した動画の「使用素材」タブで、**どのカットがどこから来たのか**を時間つきで確認できます。

```
使用素材
  ユーザー素材   IMG_001.jpg  0:03〜0:06
                 beach.mp4    0:08〜0:11（元素材 0:02〜）
  AI生成         ○○           0:13〜0:15
```

プレビューのタイムラインでクリップをクリックすると、そのカットの出所がタイムライン下に表示されます。

### 後から素材を追加する

制作が終わったあとでも「素材」タブから追加できます。「追加素材を反映して作り直す」を押すと、追加分を含めて全シーンを再評価し、**素材が変わったシーンだけ**を作り直してタイムラインを更新し、MP4を書き出し直します。変わらなかったシーンは再エンコードされません。

## 字幕について

字幕は制作フェーズで自動生成され、ナレーションとは別の「画面に出す短い言葉」として設計されます。

- **字幕サイズは実際の出力ピクセル数です**（設定 > 字幕）。既定値は88pxで、1080×1920のショート動画でサムネイルサイズでも読める大きさです
- 1行の文字数は、フレーム幅と字幕サイズから自動計算されます（88pxなら約10文字）。それを超える字幕は2行に折り返され、収まらない場合は「…」で明示的に省略されます
- スマートフォンのUIと重ならないよう、左右7.5%・下12%のセーフエリアを確保しています
- 焼き込みにはKairoが生成したASSファイルを使用します。フレームサイズと同じ`PlayRes`を宣言しているため、設定した数値がそのまま出力ピクセルになります（SRTをFFmpegに渡す方式では、変換時の基準解像度に応じて数倍の大きさで描画されてしまいます）
- 他の編集ソフトで使える`.srt`も同時に書き出されます

## Webリサーチについて

> Webリサーチは「この題材の動画がどう作られているか」を制作のたびに調べる機能です。「いま何が流行っているか」を継続的に蓄積する [Trend Intelligence](#trend-intelligenceトレンド収集分析) とは別の仕組みで、両方が制作に使われます。どちらも失敗しても制作は続行されます。

Full Auto / AI Co-Creationの「Webリサーチ」工程は、同じテーマの動画がどう作られているかを調べ、**共通トレンド**と**差別化機会**に分けて整理し、制作戦略に反映します。

- 送信されるのは検索クエリのみです。プロジェクトの内容や素材が外部に送られることはありません
- 取得したページの文章をそのまま使うことはありません。構成・テンポ・字幕の傾向といった抽象的な参考としてのみ利用します
- 参照したページは「調査・戦略」タブに一覧表示され、リンクから確認できます
- **オフラインでも問題ありません**。検索できない場合は「Webリサーチは実行できませんでした」と理由が表示され、ショート動画の一般的な定石を使って制作が続行します
- 取得先のURLは検証され、内部ネットワーク宛（localhost・プライベートIP等）やhttp/https以外のURLは取得しません

## 動画生成機能 (実験的)

写真をアップロードして短いImage-to-Video動画をローカルで生成できます(エディタ画面の`生成`タブ)。クラウドAPIは一切使用せず、[Stable Video Diffusion (img2vid)](https://huggingface.co/stabilityai/stable-video-diffusion-img2vid) をCPU上でPyTorch/diffusers経由で実行します。

### セットアップ

`npm run setup` では動画生成用の依存関係(PyTorch/diffusersなど、数百MB)はインストールされません。マルチGBのダウンロードを伴うため、使う場合のみ明示的にインストールしてください。

```powershell
backend\.venv\Scripts\pip install -r backend/requirements-videogen.txt
```

初回生成時にStable Video Diffusionのモデル本体(約9.5GB)を自動ダウンロードし、`data/models/`に保存します(以降はオフラインで再利用されます)。

### 使い方と制約

1. `生成`タブを開き、画像(JPG/PNG/WebP)をドラッグ&ドロップ
2. 「Generate」を押すとジョブが開始し、進捗が表示されます
3. 完了すると生成された動画がプロジェクトのMedia Binに自動追加されます(通常の読み込み動画と同じように編集・タイムライン追加が可能)

**重要な制約(実機検証済み)**:

- **CPU実行のみ**: このPC(Intel Core Ultra 7 155H / Arc内蔵GPU)にはIntel GPU/OpenVINO/DirectML等のアクセラレーションは未実装です。生成は非常に低速です(下記実測値参照)。
- **テキストプロンプト非対応**: Stable Video Diffusionのimg2vidパイプラインには文字起こしタキストエンコーダがなく、入力画像と動きの強さのみから生成されます。プロンプト欄はUI上に残していますが、このエンジンでは無視されます(将来、プロンプトに対応するエンジンを追加する際のための共通インターフェースです)。
- **非商用ライセンス**: Stable Video Diffusion Non-Commercial Research Community Licenseのため、商用利用不可です。個人利用・検証目的に限られます。

### 実機検証結果 (このPC: Intel Core Ultra 7 155H / RAM 32GB / CPU実行)

| 設定 | 解像度 | フレーム数 | ステップ数 | 実測時間(推論のみ) |
|---|---|---|---|---|
| 軽量(APIデフォルト) | 384×256 | 8 | 6〜10 | 約4.7分(6ステップ時、47秒/ステップ) |
| モデルデフォルト | 512×320 | 14 | 15 | 約35分以上(135秒/ステップ、実測は5/15ステップで打ち切り時点の推定) |

軽量設定をAPI/UIのデフォルトとしています。`推定生成時間`はこの実測値から機械が算出した目安で、確定値ではありません(design doc section 15の方針通り)。

### 動画生成エンジンの追加

`backend/app/services/video_engines/`配下に`VideoGenerationEngine`を実装したクラスを追加し、`video_engines/__init__.py`の`_REGISTRY`に登録することで、別のモデル(将来的なIntel GPU対応版・より高品質なモデルなど)に差し替え/追加できます。Kairo本体やUIは特定モデルに依存しません。

## トラブルシューティング

### よくあるエラーと対処方法

| 症状 / エラー | 原因 | 対処方法 |
|---|---|---|
| `npm run setup` で `Python 3.10以上が見つかりません` | PythonがPATHに無い、または未インストール | Python 3.10をインストールし、インストール時に「Add python.exe to PATH」をチェック。インストール後はターミナルを開き直す |
| `backend/.venv が見つかりません。先に npm run setup を実行してください。` | セットアップ未実行、または `backend/.venv` を削除した | `npm run setup` を実行 |
| 起動時に `'ffmpeg' was not found on PATH` | FFmpeg未インストール、またはPATH未反映 | `winget install Gyan.FFmpeg` を実行後、ターミナルを開き直す。`ffmpeg -version` で確認 |
| ブラウザで開いても真っ白 / APIエラーが出る | バックエンドが起動していない、またはポート不一致 | `npm run dev` の出力でバックエンド (`uvicorn`) がエラー無く起動しているか確認。`http://127.0.0.1:8756/api/health` が `{"status":"ok"}` を返すか確認 |
| `LM Studio: 未接続` と表示される / AI編集が失敗する | LM StudioのLocal Serverが起動していない | LM Studioを起動し、`Developer`タブで`Start Server`を押す。ポートを変更している場合は `backend/.env` の `KAIRO_LLM_BASE_URL` を合わせる |
| 字幕生成の初回実行が非常に遅い / フリーズしたように見える | faster-whisperのモデルをHugging Faceから初回ダウンロード中 | 初回のみインターネット接続が必要です。しばらく待ってください（`KAIRO_WHISPER_MODEL` を `tiny` や `base` に下げると軽くなります） |
| `EADDRINUSE` / ポートが既に使用されています (`8756` または `5173`) | 他プロセスが同じポートを使用中、前回のプロセスが終了していない | タスクマネージャーで `python.exe` / `node.exe` を確認して終了するか、`KAIRO_PORT` で別ポートを指定して起動 |
| 制作が「AIモデルの応答が時間内に返りませんでした」で止まる | モデルが大きく、PCの処理能力に対して生成が遅い | 「モデルを選ぶ」からより小さいモデル（2B〜4B級）に切り替える。または `backend/.env` の `KAIRO_LLM_TIMEOUT` を延ばす。停止した制作は「続きから再開」で途中から再開できます |
| 制作の最初のリクエストだけ極端に遅い | モデルがダウンロード済みだがメモリに読み込まれておらず、LM Studioが読み込み中 | 正常な動作です。開始画面の「モデルを選ぶ → 今すぐ読み込む」で事前に読み込んでおけます |
| 「Webリサーチは実行できませんでした」と表示される | オフライン、または検索サービスに到達できない | 制作は一般的な定石を使って続行されるため、対処は不要です。リサーチを使いたい場合はネットワーク接続を確認してください |
| ナレーションが入らない / 「音声合成が使えない」と表示される | Windows以外のOS、または音声がインストールされていない | Windowsの「設定 > 時刻と言語 > 音声」から音声を追加。無い場合は字幕のみの動画として完成します |
| チャットで指示しても「制作の実行中は変更を適用できません」と出る | Full Autoの実行中は競合を避けるため変更を受け付けません | 「一時停止」を押してから指示するか、完成を待ってください |
| 品質チェックに「自動修正不可」の指摘が残る | 構成や映像の作り直しなど、機械的に直せない内容 | AI Co-Creationのチャットから「Scene 3をもっと面白くして」のように具体的に指示してください |
| トレンドが「蓄積されたトレンドデータがまだありません」と表示される | 起動直後で、Workerがまだ1回も収集していない | 起動から約20秒後に最初の収集が走ります。待てない場合は 設定 > トレンド の「今すぐ更新」を押してください。データが無い場合もジャンルの定石で制作は続行されます |
| トレンド取得元が「未接続」のまま | ネットワークに到達できない、または取得元が一時的に応答しない | 設定 > 接続サービス に各取得元の実際のエラー内容が表示されます。トレンドが取れなくても動画制作機能は停止しません |
| YouTubeのトレンドが「未設定」と表示される | `KAIRO_YOUTUBE_API_KEY` が未設定（既定） | 任意機能です。使う場合は Google Cloud Console でYouTube Data API v3を有効化してAPIキーを作成し、`backend/.env` に設定してください |
| 取り込んだBGMが自動制作で使われない | ライセンスが「不明」のままになっている | 設定 > 素材ライブラリ で該当素材のライセンスを選択してください。ライセンス不明の素材をKairoが自動で使うことはありません |
| フォントのダウンロードが「ライセンスファイルが見つからなかった」で失敗する | 配布元のディレクトリにライセンスファイルが無い | 仕様どおりの動作です。ライセンスを確認できないフォントは取得しません。別のフォントを選んでください |
| 「GitHub APIのレート制限に達しました」でフォント取得が失敗する | 未認証のGitHub APIは1時間あたり60リクエストまで | 1時間ほど待ってから再試行してください |
| BGMのBPMが「テンポ検出なし」になる | 環境音やパッドなど、拍のはっきりしない音源 | 正常な動作です。Kairoは根拠のないBPMを表示しません。この場合ビート同期は行わず、シーン境界でカットします |
| 完成動画レビューで「音量が目安より小さい」と指摘される | BGMのみの構成で、ミックス後の音量が配信基準(-14 LUFS)より低い | 自動改善ループが有効なら次の反復でBGM音量が自動調整されます。手動で調整する場合はタイムラインのBGMクリップの音量を上げてください |
| 自動改善が1回も走らない | 初回レビューが目標スコアに達している、または自動修正できる指摘が無い | 正常な動作です。理由は制作ログに表示されます。目標スコアは 設定 > 接続サービス の「自動改善ループ」から変更できます |
| 自動改善でスコアが下がった | 改善が別の軸に悪影響を与えた（尺の調整でテンポが崩れる等） | 最終版には**最もスコアの高い版**が自動的に採用されます。各反復のMP4も `data/projects/<id>/renders/` に残っています |
| 完成動画レビューが「完成動画を解析できませんでした」になる | 書き出しファイルが見つからない、またはffprobeが失敗した | 書き出しジョブのログ (`data/projects/<id>/logs/`) を確認してください。レビューが失敗しても動画自体は完成しています |
| 制作が `script`(脚本) 工程でタイムアウトする | ローカルLLMの生成が制限時間を超えた | エラー画面に原因の候補が表示されます。特に **画像対応(Vision)モデルで文章生成している** 場合はテキスト専用モデルを併せてロードしてください（素材解析だけVisionモデルが使われます）。LM Studioのアイドル時自動アンロード(idle TTL)を無効にするのも有効です |
| 制作中に `Model reloaded` エラーが出る | LM Studioが処理中にモデルを入れ替えた | Kairoが自動で1回だけ再試行します。2回続けて失敗した場合のみエラーになります |
| 「AIモデルがLM Studio側でクラッシュしました」と表示される | モデルのプロセスが停止した（多くはメモリ不足） | 動画の書き出しと大きなモデルの同時実行を避けてください。LM Studioでモデルを読み込み直すか、より小さいモデルに切り替えます。なお**Webリサーチなど任意工程でのクラッシュは制作を止めません**（定石にフォールバックして続行します） |
| 動画にイラスト風の背景が出てくる | ユーザー素材が不足しており、Kairoが補完した | 素材が足りないシーンは「Web素材 → AI生成 → Kairoが構成した背景」の順で補完されます。どのシーンが何で補完されたかは「使用素材」タブで確認できます。実写にしたい場合は写真を追加して「素材を再評価」してください |
| 別端末からアクセスできない | LAN公開の設定が未対応（デフォルトは`localhost`限定） | [LAN内の別端末からアクセスする方法](#lan内の別端末からアクセスする方法) を参照 |
| `npm run build` / `npm run dev` で `EPERM` や権限エラー | ウイルス対策ソフトやOneDriveの同期がファイルをロックしている | リポジトリをOneDrive等の同期対象外のフォルダに置く、または対象ソフトの除外設定に追加 |
| PowerShellで `.ps1 は実行できません` のようなエラー | 実行ポリシーの制限（このプロジェクトのスクリプトは `.mjs`/Node.js製のため通常は該当しません） | `npm run <script>` はNode.jsで実行されるため影響を受けません。他のツールで発生した場合はそのツールのドキュメントを参照 |

### それでも解決しない場合

1. `npm run check` を実行し、フロントエンドの型エラー・lintエラーやバックエンドのimportエラーが無いか確認してください
2. バックエンドのログ（`npm run dev` を実行しているターミナルの出力）にPythonの例外スタックトレースが出ていないか確認してください
3. `data/projects/<プロジェクトID>/logs/` にレンダリングジョブのログが出力される場合があります
4. 設定 > 接続サービス を開くと、LLM・FFmpeg・faster-whisper・TTS・トレンド取得元・素材取得元の接続状態と、失敗している場合の具体的な対処方法が表示されます
5. 制作が完了したプロジェクトには `data/projects/<プロジェクトID>/production-report.json` と `assets-used.json` が出力されます。どのモデル・どの素材で作られたかはここで確認できます

## 開発者向け情報

### npm scripts 一覧 (リポジトリルート)

| コマンド | 内容 |
|---|---|
| `npm run setup` | 初回セットアップ（Python venv作成・pip install・npm install・.env作成・ffmpeg確認） |
| `npm run dev` | 開発サーバー起動（バックエンド `--reload` + フロントエンド Vite dev server） |
| `npm run build` | フロントエンドの本番ビルド (`frontend/dist/` を生成) |
| `npm run start` | 本番モード起動（未ビルドなら自動ビルドしてから、`--reload`無しのバックエンド + `vite preview`） |
| `npm run db:init` | SQLiteデータベースのテーブルを明示的に初期化（通常は起動時に自動実行されるため任意） |
| `npm run check` | フロントエンドのlint (`oxlint`) + 型チェック (`tsc -b`)、バックエンドのimport確認をまとめて実行 |

いずれもリポジトリのルートで実行してください（内部で `backend/` `frontend/` 双方のプロセスを起動・管理します）。

### バックエンド個別コマンド

```powershell
# 仮想環境を有効化（任意。npm scriptsは有効化なしで直接venvのpythonを呼びます）
backend\.venv\Scripts\Activate.ps1

# APIドキュメント (Swagger UI)
# npm run dev 実行中に http://127.0.0.1:8756/docs を開く
```

### フロントエンド個別コマンド

```powershell
npm --prefix frontend run dev       # devサーバーのみ
npm --prefix frontend run build     # ビルドのみ
npm --prefix frontend run preview   # ビルド済みdistの配信のみ
npm --prefix frontend run lint      # oxlintのみ
```

### 技術スタック

- バックエンド: FastAPI, SQLAlchemy (SQLite), faster-whisper, FFmpeg (subprocess経由)
- フロントエンド: React 19, TypeScript, Vite
- AI (テキスト): LM Studio等のローカルLLM (OpenAI互換 `/v1/chat/completions`、状態取得は LM Studio の `/api/v0/models` も利用)
- 映像素材生成: Pillow によるプロシージャル合成 (追加ダウンロード不要) / 任意で diffusers
- 音声: Windows SAPI (System.Speech) によるナレーション、FFmpegによるBGM・効果音の合成
- AI (動画生成・実験的): PyTorch (CPU版) + diffusers + Stable Video Diffusion (`requirements-videogen.txt`、任意インストール)
